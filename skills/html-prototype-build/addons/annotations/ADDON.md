# Formal Product Notes Addon

## Capabilities

Adds a right-hand notes rail, SVG connectors, mobile note switching, and business-action lightning to a prototype.

## Dependencies

- Stable target anchors; prefer an element's existing `id`.
- `window.__PROTOTYPE_NOTES__` snapshot.
- `runtime/client/core/state.js` provides `PrototypeViewers`.
- `runtime/client/notes/model.js` provides scenario metadata and pure `when` matching.
- `runtime/client/notes/viewer.js` provides read-only notes DOM/connector rendering; formal delivery also loads `runtime/client/core/display-mode.js` for `product-only`.
- Snapshot uses explicit `scenarios`; deep links use `?scene=<id>`.

## Boundaries

- This Addon does not provide product navigation, forms, data, or feedback components.
- Annotation-layer visuals must not be written into the selected UI pack's product Tokens.
- Mark review pins, Notes editor, Inspector, and the local server are not part of this Addon.
- The Addon only consumes current state to decide note display; it must not add new business state sources.
- Do not add new `data-*` for state; use `data-prototype-note-target` as an anchor fallback only when no suitable `id` exists.

## Visual constraints

- Prototypes with a right-hand notes rail use a two-column layout: product area `minmax(720px, 82%)` on the left, notes area `minmax(240px, 18%)` on the right, each scrolling independently.
- The number of annotation pins is determined by semantic units that need explanation; there is no fixed upper limit. Note indices are generated by the Viewer in card order.
- `data-ui-interactive` rules are in [generation-contract.md §5](../../references/generation-contract.md#5-annotations); coral `#ff8d6b` belongs to the annotation layer only and must not enter UI pack product Tokens.
